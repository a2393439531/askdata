# 员工问数 AI 智能体 · 产品设计

> 文档版本：v1.0 ｜ 2026-10-06 ｜ 项目代号：**askdata** ｜ 品牌：通用名"HR 问数智能体"（原创实现，不沿用任何第三方产品名称）

---

## 1. 产品定位

**一句话**：让不懂 SQL 的 HR / 管理者用中文直接问人力数据，系统自动生成 SQL、执行并给出图表与一句话解读。

**解决的痛点**
- HR 取数依赖 IT / 数据同事，排期慢、口径反复对不齐；
- 管理层临时要数（"各部门多少人？""P 序列平均薪资？"），Excel 透视表做一次算一次；
- 敏感人力数据（薪资、离职风险）缺乏行级/字段级权限管控，靠"发脱敏表"人治。

**目标用户**：50–2000 人规模企业的 HR 部门、用人部门管理者、审计/合规人员。

**非目标**：不做通用 BI（不做拖拽式报表设计器），不做 OA 审批流。

## 2. 用户角色

| 角色 | 说明 | 数据范围典型配置 |
|---|---|---|
| super_admin（超级管理员） | 系统拥有者：管账号、管模板、看全量审计 | all |
| admin（管理员） | HR 总监/技术总监：管模板、看审计、问数 | own_dept 或 all |
| operator（操作员） | HR 专员：问数、用模板、导 CSV | own_team / own_dept |
| readonly（只读） | 审计员/旁听：只能问数、看自己的历史 | self_only |

**数据范围**四档：`all`（全公司）/ `own_dept`（本部门）/ `own_team`（本二级部门）/ `self_only`（仅本人）。

## 3. 功能模块拆解

```
员工问数 AI 智能体
├── 1. 自然语言问数（核心）

│   ├── 结果：数据表 + 一句话解读 + 自动图表

│   ├── 聚合统计→柱状图 / 时间序列→折线图 / 占比→饼图 / 明细→表格

├── 3. 问题模板
│   ├── 按分组管理（组织概览/薪酬分析/人员画像/风险监控/绩效分析）
│   ├── 模板存固定 SQL，执行秒级返回
│   └── 新增/编辑/删除/执行
├── 4. 表字段字典
│   └── 按表分组展示：字段名/类型/主键/非空/默认值
├── 5. 查询历史与收藏
│   ├── 自动记录：问题/模型/SQL/行数/图表/耗时
│   └── 收藏、重问、删除（super_admin 可删任意）
├── 6. 用户管理（super_admin）
│   ├── 账号增删改查：用户名密码/角色/数据范围/关联员工ID/表字段白名单/启用禁用
│   └── 保护策略：不能删自己；至少保留 1 个 super_admin
├── 7. 审计日志
│   ├── 记录：登录/问数/模板执行/CSV 导出/用户增删改
│   ├── 字段：操作人/详情/IP/耗时/结果/时间
│   └── 按用户名筛选
├── 8. CSV 导出
│   └── 查询结果导出 CSV（UTF-8 BOM，Excel 直接打开），记审计
└── 9. 登录与鉴权
    ├── 用户名密码登录，JWT（HS256）
    └── 测试账号一键填入
```

## 5. 核心流程：问数流程时序

```
用户            前端              后端 API            Text2SQL 服务        大模型        SQLite
 │               │                  │                    │                │              │
 │─提问────────→│                  │                    │                │              │
 │               │─POST /chat/ask─→│                    │                │              │
 │               │                  │─ ① 鉴权+取用户权限 ─│                │              │
 │               │                  │─ ② 无关问题过滤 ──→│                │              │
 │               │                  │                    │─ ③ 有Key?调用模型│              │
 │               │                  │                    │←──返回SQL──────│              │
 │               │                  │                    │  无Key?模板匹配 │              │
 │               │                  │←─ ④ SQL安全校验 ───│                │              │
 │               │                  │   (SELECT限定/白名单/作用域注入)     │              │
 │               │                  │─ ⑤ 执行SQL ──────────────────────→│              │
 │               │                  │←─ 结果集 ─────────────────────────│              │
 │               │                  │─ ⑥ 图表类型判定+一句话解读 ───────│              │
 │               │                  │─ ⑦ 写历史+审计 ──────────────────→│              │
 │               │←─ 返回结果 ──────│                    │                │              │
 │←渲染图表+表格─│                  │                    │                │              │
```

**图表判定规则**：`auto` 时——结果含时间列且为序列 → line；含"占比/分布"或分类≤8 且为聚合 → pie；GROUP BY 聚合 → bar；否则 table。前端可手动覆盖。

## 6. 数据表设计（ER）

```
users 1───* query_history        users 1───* audit_log
users 1───* question_template    employee 1───* salary
                                 employee 1───* attendance_summary
                                 employee 1───* performance
                                 employee 自关联 manager_id
```

### 6.1 users（系统用户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增主键 |
| username | TEXT UNIQUE NN | 登录名 |
| password_hash | TEXT NN | SHA-256(盐+密码) hex |
| salt | TEXT NN | 随机盐 |
| role | TEXT NN | super_admin/admin/operator/readonly |
| data_scope | TEXT NN | all/own_dept/own_team/self_only |
| employee_id | INTEGER NULL | 关联 employee.id（own_team/self_only 定位用） |
| allowed_tables | TEXT NULL | JSON 数组；空=不限 |
| allowed_columns | TEXT NULL | JSON {表:[字段]}；空=不限 |
| is_active | INTEGER NN | 1 启用 / 0 禁用 |
| created_at / updated_at | TEXT NN | ISO 时间 |

### 6.2 employee（员工主数据，演示约 24 字段）

id(PK), name(NN), gender, birth_year, department(NN), sub_department, position, level（如 P5/M2）, manager_id(FK自关联), hire_date, education, phone, email, id_card_area, political_status, marital_status, children_count, hometown, address, work_status, entry_channel, contract_type, created_at

### 6.3 salary（薪资，按月）

id(PK), emp_id(FK), year, month, base_pay, bonus, gross_pay, UNIQUE(emp_id, year, month)

### 6.4 attendance_summary（考勤汇总，按月）

id(PK), emp_id(FK), year, month, work_days, overtime_hours, leave_days, late_count, UNIQUE(emp_id, year, month)

### 6.5 performance（绩效，按季度）

id(PK), emp_id(FK), year, quarter, kpi_score, rating, UNIQUE(emp_id, year, quarter)

### 6.6 query_history（查询历史）

id(PK), user_id(FK), question, model, sql, row_count, chart_type, elapsed_ms, status（success/error）, error_msg, is_favorite(0/1), created_at

### 6.7 question_template（问题模板）

id(PK), group_name（组织概览/薪酬分析/人员画像/风险监控/绩效分析）, title, question, sql, chart_type, created_by(FK users), created_at, updated_at

### 6.8 audit_log（审计日志）

id(PK), user_id(FK NULL), username, action（login/chat/template_execute/export_csv/user_create…）, detail（JSON/文本）, ip, elapsed_ms, result（成功/失败）, created_at

## 8. 安全策略

1. **SQL 白名单执行**：只允许单条 `SELECT`（正则+关键字双重检查，拦截 INSERT/UPDATE/DELETE/DROP/ALTER/--/; 等）；表名、字段名必须命中白名单（users/audit_log 等权限表默认不在问数白名单内）。
2. **作用域注入**：`own_dept/own_team/self_only` 用户查询命中 employee 表时，自动追加 `AND` 条件；无 WHERE 时自动补 WHERE（作用于 GROUP BY/ORDER BY/LIMIT 之前）。
3. **无关问题过滤**：问题不含数据意图关键词且模板匹配失败时，拒绝生成并提示"仅支持人力数据查询"。
4. **密码**：SHA-256 加盐存储；登录失败不透露"用户名不存在/密码错误"之分（统一提示）。
5. **账号保护**：不能删除自己；系统至少保留 1 个启用的 super_admin；禁用账号 JWT 即刻失效（每次请求校验 is_active）。
6. **审计**：登录、问数、模板执行、导出、用户变更全部落审计日志，含 IP 与耗时。
7. **JWT**：HS256，密钥走环境变量，默认 8 小时过期。
